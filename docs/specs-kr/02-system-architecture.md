## 3. 프록시 패턴

### 3.1 업그레이드 구조

모든 핵심 컨트랙트는 Transparent Proxy 패턴을 사용합니다:

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Proxy Pattern                                 │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  ┌───────────────────┐      ┌───────────────────────────────┐      │
│  │ TransparentProxy  │─────►│      Implementation           │      │
│  │                   │      │                               │      │
│  │ - ProxyStorage    │      │ - SeigManagerV1_4             │      │
│  │ - _implementation │      │ - DepositManagerV1_2          │      │
│  │                   │      │ - Layer2ManagerV1_2           │      │
│  └───────────────────┘      │ - ValidatorRewardV1           │      │
│          │                   │ - RAT                         │      │
│          │                   │ - SequencerVault              │      │
│          ▼                   └───────────────────────────────┘      │
│  ┌───────────────────┐                                              │
│  │   ProxyAdmin      │                                              │
│  │   (DAO 관리)      │                                              │
│  └───────────────────┘                                              │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.2 스토리지 상속 체인

```solidity
// SeigManager 스토리지 상속
contract SeigManagerV1_4 is
    ProxyStorage,              // 기본 프록시 스토리지
    AuthControlSeigManager,    // 권한 관리
    SeigManagerStorage,        // V1 스토리지
    SeigManagerV1_1Storage,    // V1.1 추가 스토리지
    DSMath,                    // 수학 라이브러리
    SeigManagerV1_3Storage,    // V1.3 추가 스토리지
    SeigManagerV1_4Storage     // V1.4 추가 스토리지 (V3)
```

## 5. 데이터 흐름

### 5.1 시뇨리지 분배 데이터 흐름

```
┌────────────────────────────────────────────────────────────────────────────┐
│                          시뇨리지 분배 흐름                                  │
├────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. updateSeigniorage() 호출                                               │
│     │                                                                       │
│     ▼                                                                       │
│  2. L1BridgeRegistry.layer2TVL() ──► Bridged TON 조회                      │
│     │                                                                       │
│     ▼                                                                       │
│  3. SequencerVault.getSequencerDepositByLayer2() ──► 스테이킹 조회         │
│     │                                                                       │
│     ▼                                                                       │
│  4. 자격 확인: S_i ≥ θ · B_i                                               │
│     │                                                                       │
│     ▼                                                                       │
│  5. 쌍곡선 계산: y(x) = L · (x / (k + x))                                  │
│     │                                                                       │
│     ▼                                                                       │
│  6. L2별 시뇨리지: S_i = y(x) · (B̃_i / x)                                 │
│     │                                                                       │
│     ├──► 시퀀서: (1-α) · S_i ──► OperatorManager                           │
│     │                                                                       │
│     └──► 검증자: α · S_i ──► ValidatorReward.distributeL2Rewards()         │
│                              │                                              │
│                              ├──► |V_i| > 0: 검증자 균등 분배              │
│                              │                                              │
│                              └──► |V_i| = 0: DAO Treasury                  │
│                                                                             │
└────────────────────────────────────────────────────────────────────────────┘
```

### 5.2 검증자 등록 데이터 흐름

```
┌────────────────────────────────────────────────────────────────────────────┐
│                           검증자 등록 흐름                                   │
├────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 검증자가 TON.approveAndCall(wton, amount, data) 호출                   │
│     │                                                                       │
│     │ data = [RAT 주소][SystemConfig 주소]                                 │
│     ▼                                                                       │
│  2. WTON 컨트랙트가 TON → WTON 변환                                        │
│     │                                                                       │
│     ▼                                                                       │
│  3. WTON이 RAT.onApprove() 호출                                            │
│     │                                                                       │
│     ▼                                                                       │
│  4. RAT가 담보금 저장 + 검증자 활성화                                       │
│     │                                                                       │
│     │ - validatorRegistrations[systemConfig][validator]                    │
│     │ - validatorPools[systemConfig].validators.push()                     │
│     ▼                                                                       │
│  5. 이벤트 발생: ValidatorRegistered                                        │
│                                                                             │
└────────────────────────────────────────────────────────────────────────────┘
```

## 6. 이벤트 기반 통신

### 6.1 주요 이벤트

| 컨트랙트 | 이벤트 | 용도 |
|---------|--------|------|
| SeigManager | `V3SeigniorageDistributed` | 시뇨리지 분배 완료 |
| SeigManager | `EligibilityChanged` | L2 자격 변경 |
| RAT | `AttentionTestTriggered` | RAT 테스트 시작 |
| RAT | `EvidenceSubmitted` | 증거 제출 완료 |
| RAT | `ValidatorSlashed` | 검증자 슬래싱 |
| ValidatorReward | `L2RewardDistributed` | 검증자 보상 분배 |
| SequencerVault | `SequencerSlashed` | 시퀀서 슬래싱 |

### 6.2 오프체인 모니터링

```
┌────────────────────────────────────────────────────────────────────────────┐
│                         Off-chain Monitoring                                │
├────────────────────────────────────────────────────────────────────────────┤

│                                                                             │
│  1. RAT.AttentionTestTriggered 이벤트 구독                                  │
│     │                                                                       │
│     ▼                                                                       │
│  2. 선택된 검증자인지 확인 (validator == myAddress)                         │
```
