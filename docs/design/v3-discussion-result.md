## 2. 논의 상세 내용

### 2.1 Delegate Staking의 취지

**질문**: Delegate Staking이 L2 활성화 및 Bridged TON 증가라는 V3 원래 취지에 부합하는가?

**결론**:
- L1에 스테이킹하는 것이 **L2 스테이킹을 대변**하는 것으로 볼 수 있음
- L2의 볼륨을 높이는 목적에 **부합함**
- L2 내에 스테이킹 물량을 묶어두어 사용자에게 시뇨리지 분배 가능

### 2.2 기존 V2/V3 스테이킹과의 관계

| 버전 | 상태 | 비고 |
|------|------|------|
| V2 | **유지** | 기존 사용자 자산 강제 이동 불가 |
| V3 | **신규 개발 중** | 테스트넷 배포 전 단계 |
| Delegate Staking | **별도 기능** | V3에 추가되는 유틸리티 |

**마이그레이션 방안**:
- 기존 V1/V2 스테이킹 사용자를 위해
- L2 Delegate Staking으로 **쉽게 옮겨갈 수 있는 인터페이스** 제공 검토

### 2.3 시뇨리지 분배 구조

```
┌─────────────────────────────────────────────────────────────┐
│                        L1 (Ethereum)                         │
│                                                              │
│   ┌──────────────────┐      ┌─────────────────────────┐     │
│   │  SeigManager     │─────►│   OperatorManager       │     │
│   │  (시뇨리지 계산)  │      │   (시퀀서 보상 관리)     │     │
│   └──────────────────┘      └───────────┬─────────────┘     │
│                                         │                    │
│                              ┌──────────▼──────────┐        │
│                              │  Trigger Contract   │        │
│                              │  (옵션 기능)         │        │
│                              └──────────┬──────────┘        │
└─────────────────────────────────────────┼───────────────────┘
                                          │ Bridge
┌─────────────────────────────────────────┼───────────────────┐
│                        L2               │                    │
│                              ┌──────────▼──────────┐        │
│                              │  L2 Staking Contract │        │
│                              │  (시뇨리지 직접 분배) │        │
│                              └──────────┬──────────┘        │
│                                         │                    │
│                    ┌────────────────────┼────────────────┐  │
│                    ▼                    ▼                ▼  │
│              ┌─────────┐          ┌─────────┐      ┌─────────┐
│              │ Staker A│          │ Staker B│      │ Staker C│
│              └─────────┘          └─────────┘      └─────────┘
└─────────────────────────────────────────────────────────────┘
```

**분배 방식 옵션**:
1. **시퀀서 직접 분배**: 시퀀서가 시뇨리지를 받아 직접 스테이커에게 분배
2. **자동 트리거**: OperatorManager의 시뇨리지를 L2 스테이킹 컨트랙트로 자동 전송
   - ⚠️ 모든 L2가 원하지 않을 수 있어 **별도 Trigger Contract** 필요

### 2.4 신뢰 문제 및 리스크

**문제점**: L2 시퀀서가 운영을 중단할 경우 스테이킹 자산 처리

**현실**:
- Delegate Staking은 **시퀀서에 대한 신뢰**를 바탕으로 함
- L2 운영 중단 시 자산을 빼기 어려움

**해결 방안 (논의됨)**:

| 방안 | 상태 | 설명 |
|------|------|------|
| Emergency Exit | 개발 중 | L2 문제 발생 시 비상 탈출구 |
| Challenger/Validator | 백서 미포함 | L2 Proposer 역할 대체 |
| EOA 탈출 구멍 | 개발 중 | 컨트랙트가 아닌 주소에 대한 탈출 |

**권고사항**:
- 불특정 다수 L2에 대한 대처 방안 추가 검토 필요
- 상용화 전 Emergency Exit 메커니즘 구현 필수

## 3. 개발 가이드라인

### 3.1 개발 환경

```bash
# ton-staking-v3 레포지토리 기반
git clone https://github.com/tokamak-network/ton-staking-v2.git
git checkout ton-staking-v3/dev

# delegate-staking 브랜치 생성
git checkout -b feature/delegate-staking
```

### 3.2 코드 구조 원칙

**핵심 원칙**: 기존 코드를 건드리지 않고 **로직 분리**

```
ton-staking-v2/
├── src/
│   ├── stake/
│   │   ├── managers/
│   │   │   ├── SeigManagerV3_1.sol      # 기존 - 수정 금지
│   │   │   └── ...
│   │   └── interfaces/
│   │       └── ISeigManagerV3.sol       # 기존 - 수정 금지
│   │
│   └── delegate/                         # 신규 폴더 생성
│       ├── DelegateStaking.sol          # Delegate Staking 메인
│       ├── DelegateTrigger.sol          # 시뇨리지 트리거
│       └── interfaces/
│           └── IDelegateStaking.sol
```

### 3.3 필요한 추가 개발 항목

| 항목 | 설명 | 우선순위 |
|------|------|----------|
| **L2 Deposit 함수** | L1→L2 스테이킹 인터페이스 | 높음 |
| **시뇨리지 트리거** | OperatorManager 연동 | 높음 |
| **Emergency Exit** | 비상 탈출 메커니즘 | 높음 |
| **V1→Delegate 마이그레이션** | 기존 사용자 이동 지원 | 중간 |

### 3.4 테스트 방식

```bash

forge test --match-path "test/delegate/*.t.sol" -vvv
```
