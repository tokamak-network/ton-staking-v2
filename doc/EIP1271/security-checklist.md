# EIP-1271 보안 검토 체크리스트

## 보안 검토 프롬프트

```
다음 EIP-1271 구현 코드를 보안 관점에서 검토하고 개선사항을 제안해주세요:

[여기에 구현된 코드 붙여넣기]

### 검토 항목

#### 1. 서명 검증 보안
- [ ] 서명 길이 검증 (정확히 65바이트)
- [ ] s-value 범위 검증 (replay attack 방지)
- [ ] v 값 검증 (27 또는 28만 허용)
- [ ] 제로 주소 검증
- [ ] 서명 복구 실패 처리
- [ ] **다중 서명 검증 로직 정확성**
- [ ] **numConfirmationsRequired 기준 준수**
- [ ] **중복 서명자 방지 로직**
- [ ] **MultiSig 소유자 확인 (`isOwner()` 호출)**
- [ ] **MultiSigWallet 서명 기준 준수 검증**
- [ ] **비등록 소유자 서명 거부 확인**
- [ ] **서명 재사용 방지 (usedSignatures 매핑 확인)**
- [ ] **서명 해시 생성의 일관성**

#### 2. 접근 제어
- [ ] **MultiSig 지갑이 DAO Owner (DEFAULT_ADMIN_ROLE) 확인**
- [ ] MultiSig 지갑 설정 권한 확인
- [ ] admin 역할 검증
- [ ] 권한 없는 접근 방지
- [ ] **MultiSig 지갑 변경 시 권한 재확인**

#### 3. 재진입 공격 방지
- [ ] 외부 호출 최소화
- [ ] 상태 변경 순서 확인
- [ ] 재진입 가드 필요성 검토

#### 4. 가스 최적화 vs 보안
- [ ] 효율적인 검증 순서
- [ ] 불필요한 계산 제거
- [ ] DoS 공격 방지

#### 5. 에러 처리
- [ ] 명확한 에러 메시지
- [ ] 적절한 revert 조건
- [ ] 예외 상황 처리

#### 6. 상태 관리
- [ ] 상태 변수 초기화
- [ ] 업그레이드 호환성
- [ ] 스토리지 충돌 방지

### 보안 개선 제안

각 항목에 대해:
1. 현재 구현의 문제점 (있다면)
2. 보안 위험도 (High/Medium/Low)
3. 구체적인 개선 방안
4. 개선된 코드 예시

### 추가 보안 고려사항

다음 시나리오들에 대한 보안성도 검토해주세요:
- **단일 서명 검증의 보안 위험성**
- **MultiSig 소유자 변경 시 영향**
- 악의적인 MultiSig 소유자
- **서명 재사용 공격 (usedSignatures 매핑 우회 시도)**
- 프론트러닝 공격
- 메타 트랜잭션 보안
- 업그레이드 시 호환성
- **DAO Owner가 MultiSig가 아닌 경우 처리**
- **서명 저장소 오버플로우 위험**

### 테스트 케이스 제안

보안 검증을 위한 테스트 케이스들을 제안해주세요:
- 정상적인 서명 검증
- 잘못된 서명 형식
- 권한 없는 접근 시도
- 경계값 테스트
- 공격 시나리오 테스트
```

## 코드 감사 프롬프트

```
### 심화 코드 감사

다음 관점에서 코드를 심층 분석해주세요:

#### 1. 암호학적 보안
- ECDSA 구현의 정확성
- 서명 형식 표준 준수
- 해시 함수 사용의 적절성

#### 2. 스마트 컨트랙트 보안 패턴
- Checks-Effects-Interactions 패턴
- 정수 오버플로우/언더플로우
- 외부 호출 보안

#### 3. EIP-1271 표준 준수
- 인터페이스 정확한 구현
- 매직 값 반환 로직
- 표준과의 호환성

#### 4. 가스 효율성
- 불필요한 연산 제거
- 스토리지 접근 최적화
- 루프 최적화

각 항목에 대해 구체적인 개선 코드와 함께 제안해주세요.
```
