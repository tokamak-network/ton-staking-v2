# Slashing vs RAT 테스트 분석

## 개요

Slashing 테스트와 RAT 테스트는 모두 운영자(validator)의 부정행위를 감지하고 처벌하는 메커니즘을 검증하지만, 각각 다른 레이어에서 동작하며 다른 공격 시나리오에 대응한다.

## 차이점 분석

### 1. 목적 및 범위

- **Slashing 테스트**: 
  - 운영자의 중대한 규칙 위반(예: 이중 서명, 스테이킹 조건 위반)을 감지하고 자동으로 스테이크를 몰수하는 메커니즘 검증
  - 주로 운영자의 키 관리 및 컨트랙트 규칙 준수 여부를 테스트
  - 톤스테이킹 네트워크의 기본 보안 장치

- **RAT 테스트**:
  - 롤업에서의 부정확한 상태 전송(incorrect state commitment)을 감지하고 도전하는 메커니즘 검증
  - 운영자가 제출한 롤업 블록의 정확성을 다른 운영자들이 도전할 수 있는 경제적 인센티브 제공
  - 롤업의 데이터 가용성 및 상태 정확성 보장

### 2. 트리거 조건

- **Slashing**: 운영자의 명시적인 규칙 위반 시
- **RAT**: 제출된 롤업 상태의 정확성에 도전자가 제기할 경우

### 3. 경제적 인센티브

- **Slashing**: 처벌에 초점, 공격자에게 큰 손실 부과
- **RAT**: 도전자에게 보상 제공, 정확한 도전에 대해 인센티브 부여

### 4. 기술적 구현

- **Slashing**: 운영자 컨트랙트 내의 명시적 검증 로직
- **RAT**: 복잡한 도전 게임 메커니즘과 증거 제출 프로세스

## 결론

Slashing은 운영자의 기본적인 신뢰성 보장을 위한 메커니즘인 반면, RAT는 롤업의 상태 정확성을 보장하기 위한 보다 복잡한 경제적 게임 이론 기반 메커니즘임. 두 시스템은 서로 보완적으로 작동하여 전체 네트워크의 보안을 강화함.
