# TON Staking V2 테스트 명령어 정리

`docs/test/README.md`에 기재된 주요 명령어들의 역할과 상세 내용을 정리합니다.

---

## 1. `make devnet-allocs-offline`

### **역할**
E2E(End-to-End) 테스트를 수행하기 위해 모든 컨트랙트가 사전 배포된 상태의 **L1 제네시스(Genesis) 상태 파일**을 생성합니다.

### **상세 동작**
1.  **Optimism 컨트랙트 빌드**: `lib/optimism`에 포함된 Optimism 관련 컨트랙트들을 빌드하고 초기 할당(allocs) 데이터를 준비합니다.
2.  **Staking V3 컨트랙트 배포 시뮬레이션**: `./scripts/generate-allocs-offline.sh` 스크립트를 통해 TON, WTON, SeigManager, RAT 등 Staking V3의 핵심 컨트랙트들을 가상으로 배포합니다.
3.  **상태 덤프 및 제네시스 생성**: 배포된 컨트랙트들의 주소와 코드가 포함된 상태를 파일로 저장하여 `.devnet/genesis-l1-staking-v3.json` 파일을 최종적으로 생성합니다.

### **특징**
-   **일회성 실행**: 매번 테스트를 돌릴 때마다 컨트랙트를 배포하면 시간이 오래 걸리기 때문에, 미리 배포된 상태를 '스냅샷'처럼 만들어 두고 재사용합니다.
-   **실행 시점**: 테스트를 처음 시작하기 전이나, 컨트랙트 코드 또는 초기 배포 설정이 변경되었을 때 실행해야 합니다.

## 2. `make test-e2e`

### **역할**
Go 언어로 작성된 **전체 시스템 통합 테스트(End-to-End Test)**를 실행합니다.

### **상세 동작**
1.  **제네시스 파일 확인**: `.devnet/genesis-l1-staking-v3.json` 파일이 존재하는지 먼저 확인합니다.
2.  **독립된 노드 실행**: 각 테스트 케이스는 실행될 때마다 고유한 포트(Port)에서 작동하는 **독립적인 Anvil 노드**를 띄웁니다.
3.  **테스트 수행**: `op-e2e/faultproofs` 경로에 있는 Go 테스트 코드를 실행하여 실제 시스템 흐름을 검증합니다.

### **테스트 주요 항목**
-   **System Startup**: 모든 컨트랙트가 올바른 주소에 배포되어 있고 코드가 존재하는지 확인합니다.
-   **RAT(Registry of Attention Test) 시나리오**:
    -   검증자(Validator) 등록 및 TON 예치
    -   잘못된 상태 주장에 대한 DisputeGame 생성 및 RAT 트리거
    -   증거 제출 및 분쟁 해결
    -   최종적인 보상 청구 및 자산 회수 흐름

### **특징**
-   **병렬 실행**: 각 테스트가 격리된 노드에서 실행되므로 서로 간섭 없이 병렬로 빠르게 실행됩니다. (전체 약 20~30초 소요)
-   **현실적인 시뮬레이션**: 단순히 함수 하나를 테스트하는 유닛 테스트와 달리, 실제 온체인 상호작용과 시간 경과(Time Advancement) 등을 포함한 전체 시나리오를 검증합니다.
